# v80：直接眼态与原图快速通路

2026-11-24。按用户最新要求取消眼部耦合复杂逻辑，并去除原图模式的叠加与多余处理。固件仍为官方 ESP-VISION 2026.11.14，三个模型权重、眼部裁图/测量及嘴部映射保持原样。

## 眼态

每只眼独立使用本次测得的睑缝：有效值 `<= .096` 为闭眼，其余及无效值为睁眼/中性。删除双眼共同条件、三取二、连续候选、过期保持和单侧失效造成的整对冻结。模型的单帧误判也会直接反映，不用时序规则修饰。

嘴优先、眼推理通常在本帧提交后执行的原调度保留；最新眼态进入后续合成，不增加投票等待，不宣称零光学延迟。

## 原图

采样后进入独立早返回通路，直接 `lcd.write(source)`。不运行跟踪、眼嘴推理、骨架/头姿、关键点、模式标签、取景通知或猫头合成。原图不再含 LIVE 标签，也不修改输入像素。

USB 尺寸相同则直接使用源图；当前传感器输入为 240×320、协商为 320×240 时，仅做一次保持比例的格式适配。黑边只在进入或尺寸变化时清理，随后走原生 UVC 编码；避免每帧 Python JPEG 拷贝。原生编码异常时才切到原 Q40 回退路径，同一原图阶段不会重复尝试失败编码。

USB 流开关仍回到猫脸，但不再清空仍有效的跟踪；退出暂停推理的原图模式才重新建立跟踪。

## 资源与稳定性

新增 456×392 原生通知路径在含模型与 UVC 的回归里发生三次 USB 掉线，用户确认没有手动插拔。关闭视频时 105 帧通过；恢复 v78 的 320² 缓冲后，含 UVC 的 105 帧以及最终 84/90 帧回归通过。证据指向大画布路径，但未隔离具体驱动/分配器原因，不能断言固件缺陷或内存耗尽。

产品默认恢复 v78 的 **204,800 B** 共享像素块，减少 **152,704 B**。正常猫头尺寸位置不变；通知页恢复 v78 的缩放显示，文字可能较软。大画布仅留显式实验参数，默认关闭。

后续真实传感器 80 帧测试通过后，再次启动正式入口仍发生 DVP 备份缓冲申请失败及 USB 断连。因此较小默认画布也存在启动稳定性问题，前面的隔离结果不能推广为整体问题已修复。详见[启动失败记录](../evidence/v80-direct/startup-stability.json)。

## 板测

| 检查 | 结果 |
| --- | --- |
| 直接眼态/模式策略 | 本机及 MicroPython 29 项通过 |
| v78 与直接眼态对照 | 各 105 帧，嘴部、跟踪、裁框、原始眼测量全部一致；当前眼态映射逐帧匹配，UVC 均 105/105 |
| 三模式与失跟 | 最终 84 帧通过，16 帧原图推理计数不增长，UVC 84/84 |
| 按键回调与主机 UVC 重连 | 90 帧通过，短按、长按及回猫脸保持 |
| 原图输出对照 | 两版各 120 帧，首个 USB 安全切换帧排除后，119 个 v80 原图帧源 SHA 全部不变；旧版 119 帧均被标签改写 |
| 原图稳态处理耗时 | 各 105 个稳态观察，中位 116 → 81 ms，减少 30.17%；LCD 中位仍 54 ms |
| 最终运行清单 | 18 项设备字节数与 SHA-256 匹配 |
| 最终真实传感器补测 | 猫脸/叠加/原图/猫脸各 20 帧，共 80 帧，UVC 80/80；无再次掉线 |

这些是实际板上模型、LCD、USB 的固定 RGB565 输入测试。测试包装替换相机，按键测试另替换按钮输入；不是物理相机采样或实体按压。处理耗时排除夹具解码和日志/SHA 开销，不能当作真人 FPS。当前 UVC 协商 320×240 / 10Hz，也不能把设备处理能力当作 USB 实际新帧率。

前述回归期间最小物理相机初始化多次报传感器 ID 读取 `ESP_FAIL`。最终显式启动 `/flash/main.py` 后真实相机恢复可用，随后补测直接调用真实 `sensor.snapshot`，未替换传感器或图像，仅用软件序列选择三模式。80 帧通过，其中 20 帧原图中位处理 **129 ms**（采样 12 ms，LCD 56 ms）；这是现场场景，不能与固定输入 81 ms 混为同一口径，也未做同场景 v79 配对。当前协商 10Hz，仍有 LCD 和编码开销，未证明满帧率输出。

这轮没有获得有效正脸跟踪，不能据此验收真人眨眼、嘴型或光学响应。此前相机初始化失败及恢复的原因仍未知，长时间稳定性待验。本轮只读取 GPIO60/48/53 电平，没有改变硬件管脚或固件。[数值与失败范围](../evidence/v80-direct/README.md)

## 部署与回滚

入口 [start_v80.py](../runtime/v80/start_v80.py) 部署为 `/flash/mikan-v80-direct/start.py`，自启文件 [product_main.py](../runtime/v80/product_main.py) 指向此目录。依赖见 [18 项清单](../runtime/v80/runtime-manifest.json)。共享模型与角色仍沿用历史目录。

测试结束后的首次正式重启截图为 APP UNAVAILABLE；前台核对又出现相机 DVP 内存失败，已记录并请求硬复位后再次启动。最终状态见[总记录](../evidence/v80-direct/measurements.json)。单次 reset 后残留截图不足以证明自启；本轮没有验收完整物理断电启动。

v79 设备目录保留，本地原始源码/清单及安装前 main 保存在 `.tmp/product-v80/base/`。v79 是未提交工作树，不能用 Git HEAD 当作 v79 恢复点。恢复旧入口前先显式 stop；运行中只做被动 inspect/capture，所有文件读取与验证在 stop 后执行。
