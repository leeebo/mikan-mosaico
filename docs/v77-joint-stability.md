# v77 嘴眼联合稳定性

v76 的嘴部回归证明了同一批输入的嘴开度没有因眼部改动而改变。那批验收主要将眼态和口型分开变化，缺少嘴眼同时动作以及局部成像失败的情况。因此这次现象要用同一时序里的双眼、嘴、跟踪结果一起判断。

## 根因与修改

在 v76，PFLD 通过存在分数和脸部几何后，还分别在两个眼角附近检查局部像素。任意一侧缺乏局部明暗结构，旧版就调用整脸 `miss()`，清掉嘴型、脸部跟踪和双眼历史票。眼睛再能看见时，系统还要重新捕获脸和积累两票。嘴和眼分别推理仍共享这个故障路径。

v77 保留双眼参与首次整脸确认。已经确认的脸只有在当前存在分数仍达到首次确认阈值、整脸几何与边界通过、嘴和另一侧眼仍有像素支撑时，才允许单侧暂时无观测。失效眼的主裁图和复核裁图都跳过，只走该侧原有的票过期逻辑。另一侧继续判断，嘴继续使用本帧 PFLD 开度。两侧均失败、唇部证据同时丢失、半脸或离镜仍进入保护路径。三取二、口型曲线、贴图、模型权重和固件 2026.11.14 保持同一版本。

## 上板同帧对照

用公开 Talking Face 图像做彩色 RGB565 回放。下面的眩光场景在同一张明确大张嘴的图上，只合成左眼或右眼小范围的高亮区域，保留嘴部像素。每段在已建立整脸跟踪后依次进入，用两版生产算法在同一设备上运行。

| 观察项 | v76 | v77 |
| --- | ---: | ---: |
| 左眼眩光期间保住跟踪及嘴型 | 6/8 | 8/8 |
| 右眼眩光期间保住跟踪及嘴型 | 0/8 | 8/8 |
| 只撤掉一侧的局部眼睛质量信号，保住嘴型 | 0/16 | 16/16 |
| 同一控制测试中另一只仍可见的眼保住闭眼结果 | 0/16 | 16/16 |
| 两侧质量信号均撤掉，错误保持嘴型 | 0/4 | 0/4 |
| 原运动序列的半脸被接受为跟踪 | 0/5 | 0/5 |

清楚入镜的三组时序共 60 帧，覆盖张嘴时闭眼与再睁开、微笑时闭眼、抿嘴时闭眼。新旧版可见眼态、唇距、开度、跟踪和裁框逐帧一致。在大张嘴转双闭眼的阶段，居中和叠加从第 3 个采样开始同时显示闭眼和大张嘴。上述素材按动作分段重复，考察稳定状态及板上状态转换。额外给已跟踪画面分别遮住左右半屏，再切为纯背景，v77 三段均 0/6 帧误跟踪，嘴控归零。

## 仍可复现的联合问题

短眨眼受采样频率约束。Talking Face 的 60 个带明确闭眼标签的事件中，58 个的连续明确闭合段至多 6 个源帧，按源文件提供的两种时基约为 200–240 ms。叠加约 4 FPS 时，两次相机采样通常相隔约 250 ms。即使单帧判对，短动作也可能没有两票。这里计算的是采样上限，未当作实测漏判率。

抿嘴时闭眼的序列还会出现另一种独立错误。人脸跟踪稳定，双眼按时闭合，但 PFLD 把实际合拢的唇估成明显开口。低色深回放的三段稳定嘴控约为 37%、54%、42%。再把三张全彩高质量 JPEG 在板上解码成 RGB565，仍输出约 36%、43%、34%，该问题在保留更高色深后存在。其间双眼为睁、闭、睁。

联合回归以同一段输入的左眼、右眼、嘴、跟踪和时间为一组，分别保留口型单测及眼态单测作为定位信号。
